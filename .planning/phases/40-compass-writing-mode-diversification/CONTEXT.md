# Phase 40 Context — Compass 글쓰기 모드 다양성 확보

## Goal

Compass 2-pass 시스템이 구조적으로 잘 설계되어 있지만 "항상 구성과 패턴이 바뀌도록"이라는 목적에 비추어 **의도와 설계 사이의 긴장**이 존재. 현재 회전 메커니즘(5패턴 순환)은 예측 가능한 반복을 만들고, 고정 요소(H2 흐름, 요약 블록, 종결 어미)가 너무 많아 저품질 판정 회피에 취약.

## 리뷰에서 발견된 5개 개선 축

### 1. 회전 메커니즘: 순환 → 가중 랜덤

현재: `posted.json` 카운터 0→1→2→3→4→0 (5패턴 예측 가능 순환)

개선:
- 최근 2~3회 사용 패턴에 페널티, 나머지 균등 분배 (가중 랜덤 without recent repeat)
- `intro_style`과 `h2_flow`를 **독립 축**으로 분리 (5×5=25 조합 vs 현재 5)
- `intro_style` 2~3 패턴 추가 검토 (quote_lead, reverse_chronology, what_if 등)

### 2. H2 흐름: 카테고리 고정 → 조건부 재배열

현재: category별 5개 H2 고정 (같은 카테고리는 같은 구조)

개선:
- slot2_compare에 경쟁사 있으면 비교 섹션 앞으로 당기기 등 **조건부 재배열**
- H2 5개 중 3개 필수 + 2개 선택 (소재에 따라 포함/제외)
- 글 길이 1500자 고정 → 구간(1200~2500자)으로 유동화

### 3. Pass 2 제약: 동일 문체 강제 → 톤별 분기

현재: ~습니다/~합니다 고정, 차단 표현 목록 일괄 적용 → 문장 수준 n-gram 균일

개선:
- `tone` 필드에 따른 실질적 분기 (문장 길이, 비유, 호칭)
- fan_friendly → 해요체, analytical → 해라체(~이다) 가능
- 📌 요약 블록 3~4가지 변형 (불릿/서술형/질문/자연종결)

### 4. Fact-gate: 언어 혼합 → 정교화

현재: 영어 본문에서 한국어 substring 매칭 실패 → Layer 1 건너뜀 (한국어 비중 <10%)

개선:
- 고유명사 영/한 양쪽 매칭 시도
- 숫자·날짜 등 언어 중립 요소 매칭 가중치 향상
- 혼합 언어 기사에 대한 정교한 임계값

### 5. 마무리 구조 변주 (저품질 회피에 가장 효과적)

📌 요약 불릿 리스트가 매 글 끝에 붙는 것 자체가 저품질 필터 입장에서 가장 뚜렷한 템플릿 신호. 요약 블록 자체를 변형 + 가중 랜덤 결정.

## 제약

- 기존 compass.py, fact_gate.py, writer.py 동작 보존 (additive only)
- 테스트 기존 통과 항목 회귀 없을 것
- Compass JSON 9필드 구조 유지 (내부 표현이므로 검색 엔진 노출 안 됨)
- G4 fact-gate 품질 보증 장치 유지

## 검증 방법

1. 드라이런 (`compass_dryrun.py --blog`)으로 10회 이상 실행 → intro_style 분포 확인
2. 생성된 블로그 본문의 H2 수, 종결 형태, 요약 형식 분포 분석
3. 기존 테스트 (`tests/test_compass_*.py`, `tests/test_fact_gate.py`) 모두 통과
4. 저품질 감지 기준(HTML 구조 반복, 문장 수준 반복, 메타 수준 반복) 수동 점검
