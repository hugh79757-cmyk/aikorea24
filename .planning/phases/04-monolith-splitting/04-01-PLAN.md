<threat_model>

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| LLM output → validator | validate_cards/validate_year/validate_keywords validate LLM-generated thread content before publishing (Tampering gate) |
| External URL → crawler | fetch_article_body makes HTTP requests to URLs from DB — 3rd-party servers are untrusted (Spoofing) |
| Filesystem → log_failed_crawl | Failed crawl log is written to shared log directory — path is fixed (Tampering) |
| Old wrapper → new module | Strangler Fig re-export boundary — writer_v3.py must re-export fetch_article_body for narrative_pitcher.py (Availability) |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-04-01 | Tampering | validate_cards/validate_year/validate_keywords | mitigate | Output validation gates reject hallucinated content (years not in article, truncated keywords) — same behavior as original inline code |
| T-04-02 | Spoofing | fetch_article_body | accept | URLs come from trusted D1 DB (populated by RSS reader). URL validation in assemble_final provides secondary check. Accept residual risk of malicious RSS source. |
| T-04-03 | Tampering | log_failed_crawl | accept | Writes to fixed path only (`scripts/threads/logs/failed_crawls.json`). No user-controlled path. Accept. |
| T-04-04 | Tampering | narrative_pitcher.py import path | mitigate | writer_v3.py re-exports fetch_article_body via module-level import from pipeline.threads.crawler. Verified by `python3 -c "from v3.writer_v3 import fetch_article_body"` in Task 4 verify step. |
| T-04-SC | Tampering | pip installs | mitigate | No new packages installed in this phase. All 3 existing packages (openai, beautifulsoup4, lxml) were verified in 04-RESEARCH.md Package Legitimacy Audit. |
</threat_model>
