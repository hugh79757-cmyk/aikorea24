<threat_model>

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| LLM output → parse_pitches_from_text | Processes model-generated JSON — schema validation guards against malformed LLM output (Tampering) |
| LLM output → evaluate_pitch | Evaluates pitch quality with another LLM call — direction_ok check prevents fact-direction errors (Tampering) |
| Filesystem → load_pitch_history / save_pitch_to_history | Reads/writes posted.json — fixed path, no user input in filename (Tampering) |
| Old wrapper → new module | narrative_pitcher.py re-exports all public symbols from pipeline.threads.pitch + pipeline.threads.crawler (Availability) |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-04-05 | Tampering | parse_pitches_from_text | mitigate | JSON regex anchoring (`\{...\}`) rejects malformed model output. Schema validation (3 schema checks) ensures required fields present. Falls back to empty list on parse failure. |
| T-04-06 | Tampering | load_pitch_history / save_pitch_to_history | accept | Fixed path (`posted.json`). Data is JSON-serialized pitch dicts from LLM — no executable content. Accept residual risk. |
| T-04-07 | Spoofing | evaluate_pitch LLM call | mitigate | direction_ok field (criterion 3) is a hard gate — reject if LLM evaluator says narrative/twist direction mismatch. Hard fail regardless of score. |
| T-04-OS | Information Disclosure | parse_pitches_from_text regex | accept | Regex receives LLM output only (no user input). No sensitive data exposure risk. |
| T-04-SC | Tampering | pip installs | mitigate | No new packages installed. All 3 existing packages (openai, beautifulsoup4, lxml) verified in 04-RESEARCH.md audit. |
</threat_model>
