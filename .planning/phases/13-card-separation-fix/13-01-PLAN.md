# Phase 13-01: Persistent Failed Article Tracking

**Goal**: Implement persistent storage for failed article IDs to prevent infinite retry loops across launchd cycles.

**Wave**: 1

**Dependencies**: Phase 12 complete

**Gap Closure**: false

---

## Tasks

### 1. Add failed_articles.json loader/maintainer
- File: `scripts/threads/failed_articles.py`
- Functions: `load_failed_articles()`, `save_failed_article(article_id)`, `is_article_failed(article_id)`, `clear_old_entries(max_days=7)`
- Storage: `scripts/threads/logs/failed_articles.json` with schema `{"failed_ids": {}, "last_updated": "timestamp"}`

### 2. Update main_v3.py to use persistent tracking
- Import `failed_articles` module
- On startup: `load_failed_articles()` into memory set
- When `write_thread()` fails: `save_failed_article(article_id)`, add to in-memory set
- Pass `failed_article_ids` to `get_pitches()` (already supports exclude_ids)
- On graceful shutdown: persist current state

### 3. Recovery logic
- At startup, also load `failed_crawls.json` → merge into failed_articles set (same semantics)
- Clear entries older than 7 days (configurable via env var `FAILED_ARTICLE_RETENTION_DAYS`)

### 4. Manual escape hatch
- Keep `fail_article()` function for emergency adding
- Document: `python3 -c "from scripts.threads.failed_articles import save_failed_article; save_failed_article('38290')"`

---

## Success Criteria

1. `failed_articles.json` file created with proper schema
2. `main_v3.py` loads persistent failed IDs on start and survives restarts
3. Article 38290 (or any failing article) is permanently excluded after first failure, across launchd cycles
4. Old entries (>7 days) auto-purged on startup
5. All existing tests pass (no regressions)
6. New unit tests for `failed_articles.py` (test_load, test_save, test_is_failed, test_purge_old)
