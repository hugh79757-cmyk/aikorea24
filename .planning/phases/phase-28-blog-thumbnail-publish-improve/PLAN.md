## 새 계획: 28-05 — 글쓰기 로직 개선

### 목표

현재 블로그 글 생성 로직(`blog_draft_generator.py`의 `generate_draft()`)을 개선하여 **원문 근거 입력·사실 검증·독자 행동·내부 허브 연결을 강제**하고, **발행 전에 자동 검수**로 품질이 떨어지는 글을 걸러낸다.

### 변경 대상 파일

- `scripts/blog_draft_generator.py` — `generate_draft()`, 프롬프트 구성, 검수 로직
- `scripts/auto_deep_article.py` — 심층 분석기 프롬프트 (표 사용 금지 삭제 등)

### 현재 문제의 핵심 (실제 샘플 기반 진단)

**가장 근본적인 원인**: `generate_draft()`가 `a['link']`(원문 URL)를 프롬프트에 포함하지 않아서, 모델이 원문 검증도 못 하고 출처 링크도 못 만든다. 이 한 가지 누락이 아래 5가지 문제로 나타난다.

2026-08-12 무작위 추출한 발행 글 2개(코어위브 실적, 사기 급증)에서 확인된 **반복 패턴**:

1. **숫자 출처 전무**: "매출 두 배", "주가 13% 급증", "부채 약 350억 달러", "1,400% 급증", "782달러→2,764달러", "체이널리시스 조사" — 전부 검증 링크 없음. 체이널리시스 보고서 같은 명백한 원본이 있는데도 링크가 안 걸림. **E-E-A-T에서 가장 크게 깎이는 부분.**

2. **본문 전체가 일반론**: "인공지능 산업의 팽창이 가속화되면서", "선제적 투자가 중요한 분야", "기술은 도구일 뿐" — 특정 사실(숫자) 외 나머지는 어디서나 쓸 수 있는 채워넣기 문장. 검색자가 여기서만 얻을 수 있는 정보가 없음.

3. **표가 있어야 할 자리에 표 없음**: "782달러→2,764달러, 600% 증가" 같은 건 전형적인 비교표 감인데 산문으로 흘림. 코어위브 매출/부채/주가도 마찬가지.

4. **제목·본문 한영 혼합**: 목록의 절반은 영문 원제가 그대로 title/H1에 노출("General Catalyst leads $1.1B round...", "Google's Gemini app surges..."). 한국어 검색어와 매칭이 안 됨.

5. **한국 독자 관점 0**: 전부 해외 뉴스 번역·부연인데 "이게 한국 기업/개발자/투자자에게 무슨 의미인가"가 없음.

> **핵심**: 문제는 "더 길게 쓰기"가 아니라 **원문 근거를 입력하고, 사실·해석·행동을 분리해 출력하며, 발행 전에 자동 검수하는 것**.

### 작업 1: 생성 입력 확장

`generate_draft()`의 기사 조립부를 다음 정보가 포함되도록 수정:

```
[기사 {i}]
제목: {a['title']}
매체: {a['source']}
원문 URL: {a.get('link', '')}
원문 발행일: {a.get('published_at', '')}
브리핑 요약: {desc}
```

**검수 규칙 추가**: 원문 URL이 비어 있는 기사는 자동 발행하지 않고 "출처 확인 필요" 상태로 보관. 모델이 URL을 만들어내는 것이 아니라, 시스템이 보유한 URL만 Markdown 링크로 삽입.

### 작업 2: 프롬프트 구조 개편 (조건부 필수 섹션)

#### 2.1 원문 분류 (프롬프트 상단 사전 판정)

프롬프트 맨 앞에 다음을 넣어 LLM이 먼저 판정하도록 한다:

```
[사전 분석 - 반드시 먼저 수행]
아래 원문을 분석하여 다음 플래그를 판정하라. 결과는 내부적으로만 사용한다.

- has_numeric: 수치 데이터(금액/퍼센트/성능수치/사용자수/날짜별 변화)가 2개 이상 있는가? (Y/N)
- has_comparison: 비교 대상이 2개 이상인가? (기업 vs 기업, 이전 vs 이후, 모델 vs 모델) (Y/N)
- has_source_entity: 특정 출처가 명시돼 있는가? (기업 실적발표, 조사기관 보고서, 논문, SEC 공시 등) (Y/N)
- content_type: [실적/시장] | [제품출시] | [연구/논문] | [사건/논란] | [정책/규제] 중 하나
```

#### 2.2 조건 분기 규칙 (표 삽입 여부)

| 조건 | 표 삽입 | 형태 |
|------|---------|------|
| has_numeric=Y AND has_comparison=Y | 필수 | 비교표(항목·값A·값B·변화율) |
| has_numeric=Y AND has_comparison=N | 필수 | 사실 확인표(지표·수치·기준일·출처) |
| has_numeric=N | 생략 | 표 대신 핵심 요점 3줄 |
| content_type=연구/논문 | 필수 | 표 + 방법론 한 줄 명시 |

**구현 규칙**: 표 강제 시 **"표의 모든 행에 값이 채워지지 않으면 draft reject → 재생성"** 게이트 적용. LLM이 표 틀만 만들고 빈칸으로 두는 걸 막아야 함.

#### 2.3 출처 강제 (content_type 무관, 항상 적용)

```
[출처 규칙 - 위반 시 재생성]
- 본문에 등장하는 모든 수치는 출처 각주 또는 인라인 링크를 가져야 한다.
- has_source_entity=Y인 경우: 원문 출처(기관명+보고서명)를 본문에 명시하고,
  가능하면 원문 URL을 [출처] 섹션에 최소 1개 넣는다.
- 출처를 확인할 수 없는 수치는 "~로 알려졌다" 대신 문장에서 삭제하거나,
  "원문 기준" 표기를 명시한다. 추측성 수치 생성 금지.
```

#### 2.4 content_type별 필수 섹션

**공통(항상)**: 한 문장 결론(첫 120자 내) → 본문 → 한국 독자 관점 → 요약

**조건부 추가:**
- [실적/시장] → 사실확인표 + "투자/사업 관점 시사점"(단, 투자권유 아님 명시)
- [제품출시] → 스펙/가격표 + "기존 대안과 비교" + "국내 사용 가능 여부"
- [연구/논문] → 방법론/한계 + 원논문 링크
- [사건/논란] → 사실관계 타임라인 + 입장 양측 병기
- [정책/규제] → "한국 현행 제도와 비교" 필수

#### 2.5 표 사용 금지 규칙 삭제

현재 `auto_deep_article.py` 프롬프트에 있는 "표 사용 금지" 규칙을 **삭제**. 표는 모든 글에 기계적으로 넣을 필요는 없지만, 숫자·가격·성능·일정·기업 비교가 있는 뉴스에는 사실 확인 표를 필수로 하는 조건부 규칙이 적합.

### 작업 3: 발행 전 자동 검수 규칙 (heuristic + LLM 하이브리드)

생성 직후 다음 조건을 검사. 하나라도 실패하면 자동 발행하지 않고 초안 큐로 보낸다.

**원칙**: heuristic으로 충분한 것은 regex로 신속 검사(비용 낮음), LLM 판정이 필요한 것만 LLM 호출.

#### 검수 규칙 명세

| 검수 항목 | 검사 방식 | 통과 기준 |
|----------|-----------|-----------|
| **출처 없는 숫자 0건** | heuristic: 정규식으로 숫자+단위(%, 달러, 억, 배) 추출 → 같은 문단/각주에 링크·출처엔티티 있는지 확인 | 미매칭 수치 0개 |
| **첫 120자 내 결론** | heuristic: 본문 앞 120자에 결론 신호어(단정 서술) 포함 여부 → 애매하면 LLM 판정 | 통과/재생성 |
| **표 무결성** | heuristic: 표 파싱 후 빈 셀 검출 | 빈 셀 0개 |
| **제목 언어 일관성** | heuristic: title/H1에 영문 비율 40% 초과 시 fail | 한글 우선 |
| **일반론 과다** | LLM 판정: "이 문단이 특정 사실 없이 성립하는가" 문단별 채점 | 일반론 문단 30% 이하 |

#### 구현 순서

1. **heuristic 함수 4개** 우선 구현 (regex 기반, 빠르고 저렴)
   - 숫자+단위 추출 정규식: `(\d+[\.\d]*)\s*(%|억|만|달러|\$|배|배율|포인트|퍼센트)`
   - 첫 120자 결론 신호어: 단정 서술 패턴 (예: "~이다", "~로 나타났다", "~로 확인됐다", "~라는 결과다")
   - 표 파싱: Markdown 표 구문 분석 후 빈 셀 체크
   - 제목 영문 비율: title 문자열 내 영문 글자 비율 계산

2. **LLM 일반론 판정** 별도 함수 (비용 고려, 샘플 5문단 정도만)
   - 프롬프트 예: "다음 문단이 특정 사실·수치·사건 없이 일반적으로 성립하는 문장인가? (Y/N)로만 답하라"

3. 검수 실패 시 → draft reject → `generate_draft()` 재호출 또는 초안 큐 보관

> **특히 출처 없는 숫자 검수**: 숫자를 모두 막을 필요는 없지만, 모델 출력의 숫자·퍼센트·금액이 사실 확인 표 또는 인접한 출처 링크와 연결되어 있는지 검사.

#### 표본 비교 Rubric (검증용 정량 기준)

수정 전/후 각 5개 글을 **6개 항목 0/1 채점**:

| 항목 | 기준 |
|------|------|
| 1. 수치당 출처 매칭률 ≥ 90% | 본문 내 모든 수치에 출처 링크 또는 각주 존재 |
| 2. 표 1개 이상 존재 (해당 유형만) | has_numeric=Y인 글은 표 1개 이상 |
| 3. 첫 120자 내 결론 유무 | 본문 첫 120자 안에 결론 문장 존재 |
| 4. 한국 독자 관점 문단 유무 | "한국 독자에게 어떤 의미인가" 섹션 존재 |
| 5. title 한글 우선 여부 | title/H1이 한글 또는 한영 혼합 시 한글 우선 |
| 6. 일반론 문단 비율 ≤ 30% | 전체 문단 중 일반론(특정 사실 없이 성립하는 문단) 30% 이하 |

**합격선:** 수정 후 평균 5/6 이상, 수정 전 대비 +3점 이상 개선

**예상:** 수정 전 점수 0~1/6, 수정 후 4~5/6

## 검증 방법

- **드라이런**: 수정된 `generate_draft()`로 실제 기사 3~5개를 생성해보고, 프롬프트에 원문 URL이 포함되는지, 조건 분기에 따라 표·출처·섹션이 제대로 출력되는지 확인.
- **검수 게이트 테스트**: 원문 URL 없는 기사, 출처 없는 숫자가 포함된 글, 표 빈칸이 있는 글을 생성해보고 자동 발행 차단되는지 확인.
- **기존 테스트**: 275개 이상 테스트 전체 통과 확인.
- **표본 비교 (Rubric)**: 수정 전 글 5개와 수정 후 글 5개를 6개 항목(수치 출처 매칭률, 표 존재, 첫 120자 결론, 한국 독자 관점, 제목 한글 우선, 일반론 비율)으로 0/1 채점. 합격선: 수정 후 평균 5/6 이상, 수정 전 대비 +3점 이상 개선.
