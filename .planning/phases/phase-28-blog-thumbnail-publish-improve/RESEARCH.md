## 1. 실제 발행 글 표본 분석 (요약)

무작위 추출한 2개 샘플(코어위브 실적, 사기 급증)에서 **같은 패턴**이 반복됨. 잘 쓰인 한국어 문장이지만 SEO/신뢰 관점에서 치명적 결함:

### 문제 1: 숫자 출처 전무
- 코어위브 글: "매출 두 배", "주가 13% 급등", "부채 약 350억 달러" — 검증 링크 없음
- 사기 글: "1,400% 급증", "782달러→2,764달러", "체이널리시스 조사" — 명백한 원본(체이널리시스 보고서) 링크 없음
- **E-E-A-T에서 가장 크게 깎이는 부분**

### 문제 2: 본문 전체가 일반론
- "인공지능 산업의 팽창이 가속화되면서", "선제적 투자가 중요한 분야", "기술은 도구일 뿐"
- 특정 사실(숫자) 외 나머지는 어디서나 쓸 수 있는 채워넣기 문장
- **검색자가 여기서만 얻을 수 있는 정보 없음**

### 문제 3: 표가 있어야 할 자리에 표 없음
- "782달러→2,764달러, 600% 증가" → 비교표 감인데 산문으로 흘림
- 코어위브 매출/부채/주가도 마찬가지
- **표가 있어야 정보가 한눈에 들어온다**

### 문제 4: 제목·본문 한영 혼합
- 목록에서 확인된 절반의 글이 영문 원제를 그대로 title/H1에 노출
- "General Catalyst leads $1.1B round...", "Google's Gemini app surges..."
- **한국어 검색어와 매칭 안 됨**

### 문제 5: 한국 독자 관점 0
- 전부 해외 뉴스 번역·부연
- "이게 한국 기업/개발자/투자자에게 무슨 의미인가"가 없음
- **aikorea24의 차별화 포인트 부재**

## 2. 핵심 아이디어: 원문 분류 후 조건부 강제

### 원칙
"무조건 표를 넣으면 어색하고, 안 넣으면 지금처럼 산문으로 흘려버린다." → **입력 원문을 분석해서 "데이터 유형"을 먼저 판정**하고, 유형에 따라 표·출처·섹션을 조건부로 강제.

### 2.1 원문 분류 (프롬프트 상단 사전 판정)

프롬프트에 다음을 넣어 LLM이 먼저 판정하도록 한다:

```
[사전 분석 - 반드시 먼저 수행]
아래 원문을 분석하여 다음 플래그를 판정하라. 결과는 내부적으로만 사용한다.

- has_numeric: 수치 데이터(금액/퍼센트/성능수치/사용자수/날짜별 변화)가 2개 이상 있는가? (Y/N)
- has_comparison: 비교 대상이 2개 이상인가? (기업 vs 기업, 이전 vs 이후, 모델 vs 모델) (Y/N)
- has_source_entity: 특정 출처가 명시돼 있는가? (기업 실적발표, 조사기관 보고서, 논문, SEC 공시 등) (Y/N)
- content_type: [실적/시장] | [제품출시] | [연구/논문] | [사건/논란] | [정책/규제] 중 하나
```

### 2.2 조건 분기 규칙 (표 삽입 여부)

| 조건 | 표 삽입 | 형태 |
|------|---------|------|
| has_numeric=Y AND has_comparison=Y | 필수 | 비교표(항목·값A·값B·변화율) |
| has_numeric=Y AND has_comparison=N | 필수 | 사실 확인표(지표·수치·기준일·출처) |
| has_numeric=N | 생략 | 표 대신 핵심 요점 3줄 |
| content_type=연구/논문 | 필수 | 표 + 방법론 한 줄 명시 |

**구현 관점 규칙**: 표 강제 시 **"표의 모든 행에 값이 채워지지 않으면 draft reject → 재생성"** 게이트가 필요. LLM이 표 틀만 만들고 빈칸으로 두는 걸 막아야 함.

### 2.3 출처 강제 (content_type 무관, 항상 적용)

```
[출처 규칙 - 위반 시 재생성]
- 본문에 등장하는 모든 수치는 출처 각주 또는 인라인 링크를 가져야 한다.
- has_source_entity=Y인 경우: 원문 출처(기관명+보고서명)를 본문에 명시하고,
  가능하면 원문 URL을 [출처] 섹션에 최소 1개 넣는다.
- 출처를 확인할 수 없는 수치는 "~로 알려졌다" 대신 문장에서 삭제하거나,
  "원문 기준" 표기를 명시한다. 추측성 수치 생성 금지.
```

### 2.4 content_type별 필수 섹션

**공통(항상)**: 한 문장 결론(첫 120자 내) → 본문 → 한국 독자 관점 → 요약

**조건부 추가:**
- [실적/시장] → 사실확인표 + "투자/사업 관점 시사점"(단, 투자권유 아님 명시)
- [제품출시] → 스펙/가격표 + "기존 대안과 비교" + "국내 사용 가능 여부"
- [연구/논문] → 방법론/한계 + 원논문 링크
- [사건/논란] → 사실관계 타임라인 + 입장 양측 병기
- [정책/규제] → "한국 현행 제도와 비교" 필수

## 3. 검수 게이트 로직 (구현 관점)

### 원칙: heuristic 1차 → LLM 2차 하이브리드

순수 regex는 오탐 많고, 순수 LLM은 비싸고 불안정. 따라서:

- **heuristic으로 충분한 것 4개**: 출처 없는 숫자, 첫 120자 결론, 표 무결성, 제목 언어 일관성
- **LLM 필요한 것 1개**: 일반론 과다 검출

### 3.1 검수 규칙 명세

| 검수 항목 | 검사 방식 | 통과 기준 |
|----------|-----------|-----------|
| 출처 없는 숫자 0건 | heuristic: 정규식으로 숫자+단위(%, 달러, 억, 배) 추출 → 같은 문단/각주에 링크·출처엔티티 있는지 확인 | 미매칭 수치 0개 |
| 첫 120자 내 결론 | heuristic: 본문 앞 120자에 결론 신호어(단정 서술) 포함 여부 → 애매하면 LLM 판정 | 통과/재생성 |
| 표 무결성 | heuristic: 표 파싱 후 빈 셀 검출 | 빈 셀 0개 |
| 제목 언어 일관성 | heuristic: title/H1에 영문 비율 40% 초과 시 fail | 한글 우선 |
| 일반론 과다 | LLM 판정: "이 문단이 특정 사실 없이 성립하는가" 문단별 채점 | 일반론 문단 30% 이하 |

### 3.2 구현 순서

1. **heuristic 함수 4개** 우선 구현 (regex 기반, 빠르고 저렴)
2. **LLM 일반론 판정**은 별도 함수로 구현 (비용 고려, 샘플 5문단 정도만)
3. 검수 실패 시 → draft reject → `generate_draft()` 재호출 또는 초안 큐 보관

## 4. 표본 비교 Rubric (정량 평가 기준)

수정 전/후 각 5개 글을 **6개 항목 0/1 채점**:

| 항목 | 기준 |
|------|------|
| 1. 수치당 출처 매칭률 ≥ 90% | 본문 내 모든 수치에 출처 링크 또는 각주 존재 |
| 2. 표 1개 이상 존재 (해당 유형만) | has_numeric=Y인 글은 표 1개 이상 |
| 3. 첫 120자 내 결론 유무 | 본문 첫 120자 안에 결론 문장 존재 |
| 4. 한국 독자 관점 문단 유무 | "한국 독자에게 어떤 의미인가" 섹션 존재 |
| 5. title 한글 우선 여부 | title/H1이 한글 또는 한영 혼합 시 한글 우선 |
| 6. 일반론 문단 비율 ≤ 30% | 전체 문단 중 일반론(특정 사실 없이 성립하는 문단) 30% 이하 |

**합격선:** 수정 후 평균 5/6 이상, 수정 전 대비 +3점 이상 개선

**예상:** 수정 전 점수 0~1/6, 수정 후 4~5/6

## 6. 리스크

1. **LLM 일반론 판정의 비용**: 매 글마다 LLM 호출 추가 → 비용 증가. 하지만 aikorea24는 일 6건 수준이므로 비용 부담 낮음.
2. **heuristic 오탐**: 정규식 기반 숫자 추출이 날짜나 버전 번호를 오인할 수 있음 → 화이트리스트/블랙리스트로 보완 필요.
3. **표 강제 시 품질 저하**: 표가 억지로 들어가면 가독성을 해칠 수 있음 → 사용자 가독성 평가도 병행.
4. **기존 글과의 일관성**: 새 로직으로 생성된 글은 기존 글과 스타일 차이가 날 수 있음 → 점진적 적용 권고.

## 7. 결론

사용자가 제시한 5가지 문제는 **프롬프트 조건 분기 + 검수 게이트**로 해결 가능. 핵심은:

1. 원문을 먼저 분석(has_numeric, has_comparison, content_type) → 조건부 표·섹션 강제
2. 출처 없는 숫자·표 무결성·제목 언어·일관성은 heuristic으로 신속 검사
3. 일반론 과다만 LLM으로 정밀 검사 (비용 낮음)
4. 표본 비교는 6항목 rubric으로 정량 평가

이 접근은 기존 글쓰기 로직을 완전히 교체하지 않고, 프롬프트와 검수만 수정하면 적용 가능.
