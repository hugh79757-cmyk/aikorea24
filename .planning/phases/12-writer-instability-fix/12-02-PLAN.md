<objective>
Reduce pipeline latency by 50%+ and simplify retry structure — eliminate the 3-model sequential fallback, write_thread internal retry loop, and redundant validations.

**Purpose:** The 2026-07-05 log shows 1 article attempt takes ~5min wall-clock. The main contributors are:
1. Sequential 3-model fallback in chat_completion (~2min per gen/humanize call)
2. write_thread 2-attempt loop + fallback (3× total pipeline cost)
3. Humanize + fix_cards doing redundant card count validations (waste when per-card processing eliminates mismatch)

**Output:**
- `writer.py`: Parallel model race — all 3 models called concurrently, first valid response wins
- `writer.py`: Single attempt per write_thread call (no 2-attempt loop, no fallback)
- `validator.py`: Removed redundant card count checks
- `main_v3.py`: Article skip on write failure + handles single-attempt write_thread
</objective>

  <name>Task 1: Parallel model race for chat_completion in write_thread</name>
  <files>pipeline/threads/writer.py</files>
  <action>
    Replace the sequential 3-model fallback in `write_thread()`'s `chat_completion` call with a parallel race using `concurrent.futures.ThreadPoolExecutor`.

    **Current behavior (sequential fallback):**
    ```python
    content = chat_completion(
        system_prompt=system_prompt,
        messages=[...],
        temperature=temp,
        max_tokens=5000,
    )
    ```
    model_router.py internally tries MiMo (40s timeout) → DeepSeek (40s) → GPT-4o-mini (40s).
    Even when MiMo works, it waits for each model sequentially.

    **New behavior (parallel race):**
    Replace the single `chat_completion()` call in write_thread (and fallback block) with a parallel race:
    ```python
    from v3.model_router import chat_completion
    import concurrent.futures

    def _try_model(model_override):
        return chat_completion(
            system_prompt=system_prompt,
            messages=[{'role': 'user', 'content': user_prompt}],
            temperature=temp,
            max_tokens=5000,
            model_override=model_override,
        )

    models = ['mimo-v2.5', 'deepseek-v4-flash', 'gpt-4o-mini']
    content = None
    with concurrent.futures.ThreadPoolExecutor(max_workers=3) as executor:
        futures = {executor.submit(_try_model, m): m for m in models}
        for future in concurrent.futures.as_completed(futures, timeout=60):
            result = future.result()
            if result:
                content = result
                break  # First valid response wins
    ```

    **Alternative simpler approach (if model_router.py doesn't expose model_override):**
    Instead modify model_router.py's `chat_completion()` to support parallel race internally.
    
    Check model_router.py signature — if `chat_completion()` already has `model_override` param, use approach above. If not, add parallel race logic inside model_router.py.

    **Timeout strategy:**
    - Total race timeout: 60 seconds (all 3 models together)
    - Individual model timeout: not needed — the race itself limits total wait
    - If all 3 fail within 60s → return None (same as current failure behavior)

    **Edge cases:**
    - 2 models return valid response → use first one (they should be functionally equivalent)
    - 1 model returns garbage (not parseable) → parse_cards handles it; write_thread retry via main_v3
    - MiMo consistently fastest → race ensures it's used when available
    - GPT-4o-mini cheapest but slower → only used when faster models fail

    **Files to check first:**

  <name>Task 3: Article skip on write failure in main_v3.py</name>
  <files>scripts/threads/main_v3.py</files>
  <action>
    In `run_v3()`, when `write_thread(pitch, articles)` returns `[]`, add the article ID to `failed_article_ids` BEFORE continuing the retry loop.

    **Current bug (lines ~182-187):**
    ```python
    cards = write_thread(pitch, articles)
    if not cards:
        log(f'  ❌ 쓰레드 작성 실패 (시도 {attempt}/{max_retries})')
        continue  # Same article gets picked again next iteration
    ```

    **Fix:**
    ```python
    cards = write_thread(pitch, articles)
    if not cards:
        log(f'  ❌ 쓰레드 작성 실패 (시도 {attempt}/{max_retries})')
        pitch_ids = pitch.get('article_ids', [])
        for aid in pitch_ids:
            raw = str(aid).lstrip('#').strip()
            if raw:
                failed_article_ids.add(raw)
        continue
    ```

    **Why this works:**
    - `get_pitches()` already uses `exclude_ids=failed_article_ids`
    - After adding the failed article's ID, next retry iteration calls `get_pitches()` which skips that article
    - Different pitch gets selected for retry
    - If all articles excluded → `get_pitches` returns `([], set())` → retry loop exits

    **Edge cases:**
    - `article_ids` could be None or empty → `.get('article_ids', [])` handles it
    - ID could be int or str → `str(aid).lstrip('#').strip()` normalizes
    - Already excluded → set.add() is idempotent
  </action>
