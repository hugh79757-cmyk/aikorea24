<objective>
**Eliminate the retry loop caused by repeated re-selection of crawl-failed articles in the Threads pipeline.**

**Purpose:** When `get_pitches()` fails to crawl a selected article's URL, it returns `[]`. The caller `main_v3.py` retries up to 5 times, but the same `article_id` keeps getting re-selected by the LLM because there is no exclusion mechanism. This creates a loop where all 5 retries fail on the same article, wasting API calls and delaying pipeline completion for 38+ minutes.

**Solution (Research Option A):** Change `get_pitches()` return type from `list` to `tuple[list, set]` — always returns `(pitches, failed_ids)`. Add `exclude_ids: Optional[set] = None` parameter. In `main_v3.py`, maintain `failed_article_ids: set[str]` across retries and pass as `exclude_ids`. Filter excluded article_ids from the shuffled list before LLM batch processing.

**Output:** Modified `pipeline/threads/pitch.py`, `scripts/threads/main_v3.py`, `scripts/threads/v3/narrative_pitcher.py`, `tests/test_pitch.py`, `pipeline/threads/crawler.py` (enhancement).

**Reference:** `07-RESEARCH.md` — Option A (RECOMMENDED), full analysis at lines 272–400.
</objective>
