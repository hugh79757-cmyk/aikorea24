# Fix: 등록한 툴 목록 미노출 + 상세 이미지 미표시

## Problem

1. **목록 미노출**: `/tools/submit`으로 등록한 테스트 툴이 `/tools/` 목록에 안 보임.
   - 목록(`src/pages/tools/index.astro`)은 D1 `tool_submissions WHERE status='published'` 조회 (SSR, output: 'server').
   - 제출(`src/pages/api/tools/submit.ts`)은 항상 `status='pending'` INSERT → 관리자 승인(`src/pages/api/admin/tools/review.ts` → `published`) 필요.
   - 후보 원인: (a) status가 아직 'pending' (승인 미수행), (b) 제출/조회가 서로 다른 D1 (로컬 dev D1 vs 프로덕션 remote D1), (c) 목록 쿼리가 `catch { d1Rows = [] }`로 실패를 무음 삼킴.
2. **이미지 미표시**: 제출 시 업로드한 이미지(`/api/upload` → R2, `screenshot_url` 저장)가 상세 페이지에서 안 보임.
   - `src/pages/tools/[id].astro` 248-252행: `screenshotUrl`이 있으면 **텍스트 링크(`<a>🖼️ 스크린샷 보기 →</a>`)만** 렌더 — `<img>`가 아예 없음.
   - 추가 확인 필요: 저장된 URL(`/api/files/tools/.../` — trailing slash 포함)이 실제로 200을 반환하는지.

## Task 1: 목록 미노출 원인 확정 + 수정 (진단 우선)

**Files**: `src/pages/tools/index.astro` (필요시), D1 데이터 (읽기/승인)

1. **D1 상태 확인 (양쪽 모두)** — 툴 행이 어느 DB에 있는지, status가 무엇인지:
   - remote: `env -u CLOUDFLARE_API_TOKEN wrangler d1 execute aikorea24-db --remote --command "SELECT slug, name, status, screenshot_url, created_at FROM tool_submissions ORDER BY created_at DESC LIMIT 10"`
   - local: 같은 명령 `--local`
2. **분기 처리**:
   - 행이 **local에만** 존재 → dev/prod D1 분리가 원인. 프로덕션 D1에 동일 행 INSERT(원본 데이터 그대로)하고, 제출 플로우가 prod에서만 이뤄지도록 안내 문구는 넘기지 않음 (데이터 복사로 해결).
   - 행 status가 **'pending'** → 관리자 승인 수행: `POST /api/admin/tools/review` body `{"slug":"<slug>","action":"approve"}` (admin 세션 쿠키 필요) 또는 동일 결과인 `UPDATE tool_submissions SET status='published', updated_at=datetime('now') WHERE slug='<slug>'`. 승인 자체는 설계된 정상 플로우이므로 코드 수정 없음.
   - status가 이미 **'published'**인데 목록에 없음 → `index.astro`의 D1 쿼리를 같은 컬럼으로 재실행해 실패 원인 확인하고, `catch`에 `console.error`를 추가해 무음 실패 제거 (원인이 컬럼/마이그레이션 누락이면 해당 SQL 마이그레이션을 local+remote에 적용).
3. **검증**: 배포본(또는 로컬 dev) `GET /tools/` 응답 HTML에 툴 이름이 포함되어야 함.

## Task 2: 상세 페이지 이미지 표시 + 파일 서빙 확인

**Files**: `src/pages/tools/[id].astro`

1. 248-252행의 텍스트 링크만 있는 블록을 실제 이미지 렌더로 교체: `tool.data.screenshotUrl` 존재 시 `<img src={tool.data.screenshotUrl} alt={`${tool.data.name} 스크린샷`} loading="lazy" class="w-full max-h-80 object-contain rounded-xl border ...">` 표시. 링크는 이미지 클릭 링크로 유지해도 됨. `src`가 `/api/files/` 상대경로면 그대로 사용.
2. 파일 서빙 확인: Task 1에서 얻은 `screenshot_url`로 `curl -s -o /dev/null -w "%{http_code}" https://aikorea24.kr<screenshot_url>` 실행.
   - 200이면 종료. 404면 `src/pages/api/files/[...path].ts`의 rest param 매핑(trailing slash `params.path` 빈 세그먼트) 확인 후 키 정규화 수정.
   - `screenshot_url`이 NULL이면 → Task 1의 D1 진단 단계로 돌아가 제출 당시 값이 저장되었는지 확인(저장 안 됐으면 ToolForm 제출 본문/submit INSERT 경로 점검).
3. **검증**: 상세 페이지 HTML에 `<img ...screenshot_url...>` 태그 존재 + 이미지 URL이 200.
