# 프롬프트 하드코딩 패턴 제거 (fix)

## What

쓰레드 생성 프롬프트(`build_system_prompt_D()`)에서 특정 단어를 강제로 사용하도록 지시하는 하드코딩 패턴 3건을 제거:

1. **1번 카드 stanza1**: `줄1 통념도입("~라는 말, 모두가 믿었음")` → `줄1 통념도입`
   - "모두가 믿었음"이 모든 쓰레드에 강제 삽입되어 문장이 어색해짐
2. **1번 카드 stanza2**: `줄1 전환시그널("근데")` → `줄1 전환시그널`
   - 모든 전환부가 "근데"로 시작해야 한다는 강제성 제거
3. **2번 카드 줄1**: `전환시그널("하지만", "근데", "그런데")` → `전환시그널("하지만", "그런데")`
   - "근데"를 예시 목록에서 제외 (너무 구어체)

## Why (버튼이 안 눌린 이유)

**1. 패턴이 '예시'로만 인지됨**  
프롬프트 작성 당시 `"~라는 말"`과 `"근데"`는 모범 예시를 보여주는 용도로 삽입되었지만, LLM은 이를 **"반드시 따라야 할 템플릿"**으로 학습하여 매 쓰레드마다 동일한 어투를 반복하게 됨.

**2. 검증 파이프라인이 문법/구조만 검사했음**  
`validate_card_structure()`는 카드 길이·한글 비율·문장 완성도만 검사했고, **특정 단어의 강제 사용 문제는 감지하지 못함**.  
프롬프트 내용 자체를 검증하는 단계가 없었음.

**3. "일단 동작하니까" 방치**  
파이프라인이 발행에 성공하고 있었고, 문법적으로도 문제가 없었기 때문에 프롬프트의 표현 다양성 문제를 별도 버그로 인식하지 못함. 쓰레드의 '자연스러움'은 자동 검증 대상이 아니었음.

**4. 실사용 피드백 부재**  
실제 발행된 쓰레드에 대해 "모든 글이 비슷한 패턴으로 시작한다"는 문제가 제기된 적이 없어 우선순위에서 밀렸음.
