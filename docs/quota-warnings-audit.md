**사전(임계치 도달 前) 경고는 무료티어 어느 항목에도 없다.** 유일한 경고는 **D1의 도달 시점 이메일**(2026-09-01 시행, "when the daily limit is reached"). 나머지 항목(Workers 요청·KV·R2 등)은 초과 직후 **오류로만** 알린다. 리셋은 전부 **00:00 UTC = 09:00 KST**(R2는 월간). 따라서 D1에 도입한 로컬 `check_quota(0.8)` 가드(30분 주기, 18스크립트)가 **우리 파이프라인의 유일한 사전 경고 계층**이다.

## 관찰

1. **유일한 "전 감지"는 우리가 만든 것**: CF는 도달(100%)만 알리거나 침묵-오류. `check_quota(0.8)`가 80% 차단으로 전 항목에 걸친 유일한 사전 경고 계층이다.
2. **리셋 시간 = 09:00 KST**: 파이프라인 (09:00 이후~자정)이 윈도우를 소진하면 다음 날 아침 9시까지 D1 전 멈춤 — 감지 지연이 아침 9시까지 지속됨.
3. **최근 9일 한도 초과 3건 실발생 (계정 합산 GraphQL 실측)**:
   - **10-09 쓰기 183.4%** (183,390) — 마이그레이션 백필일
   - **10-10 읽기 109.2%** (5,457,745) — `code 7500` 저녁 정전 사건 (= 강제차단 실증, d1-budget.md §4 문서화)
   - **10-14 읽기 106.4%** (5,318,301) — 사건일. 차단·이메일 공지 시점이었음 (이메일 수신은 [부분검증] — 신계정 수신함 확인 필요)
   - 분해: 10-14에 `aikorea24-db` 단독 3,358,451 (67%) — 나머지 약 2.0M reads는 `aikorea24-emdash-db` 등 계정 내 다른 DB 발생
4. **유료 전환 시**: threshold 기반 Usage Based Billing 알림 + budget alert(모든 제품) 사용 가능 — 성장 재개 시 경고-계층 해결책.
5. Workers 요청 12.8%는 여유 넉넉하지만, 무료에서 Error 1027은 **사전 없이** 전 Worker 요청 실패로 이어짐 — 주간 1회 관측(GraphQL) 권고.
6. **쓰기 가드 갭**: `check_quota`는 읽기 임계만 검사 (쓰기 검사 미포함). 초과 3이(가) 중 2건이 쓰기 초과 (183%, 95%) — 쓰기 임계(예: 90%) 추가 권고.
