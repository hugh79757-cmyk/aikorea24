## 1. 재측정 명령 (각 1줄)

```bash
cd ~/Projects/aikorea24
python3 scripts/d1_usage_report.py --history 6 --by-db   # 일자별 총량 + DB별 분해
python3 scripts/d1_usage_report.py --unit 6              # 보조 지표: 행/요청 단가
```

- `--history N` = 최근 N일(UTC) 일자별 읽기·쓰기 + 한도 대비 %. `--by-db` 를 붙이면 DB별로 갈라 보여준다.
- `--unit N` = 그 DB 를 서빙하는 Worker 요청 수로 읽기를 나눈 **단가**(트래픽 교란을 나누어 보기 위한 보조 지표).
- 2026-10-21에 `--history 6` 을 돌리면 `10-16 ~ 10-21` 이 나온다 = 비교 기준 3일(10-16·17 + 부분적용 10-18) + 적용 후 3일(10-19~21).
- 기존 경로(인자 없이 실행 = 오늘 누적 1줄 + 경보 판정)는 **변경하지 않았다**. 두 모드는 인자를 줬을 때만 동작한다.

## 4. 이 계획이 답하지 못하는 것 (한계 — 먼저 읽을 것)

1. **per-path 귀속 불가**: 토큰에 `com.cloudflare.api.account.zone.analytics.read` 가 없어 어느 URL이 읽기를 만들었는지 알 수 없다. D1 analytics 도 `databaseId`·`date`·`datetimeHour` 세 차원만 지원한다(2026-10-17 실측). ⇒ **①의 서빙 절감을 계정 총량에서 분리 확인할 수단이 없다.**
2. **요청당 단가는 노이즈가 크다**: 2026-10-18 시간대 실측에서 53 ~ 889행/요청까지 요동했다(그날 맞은 페이지 구성이 시간대마다 달라서다). 단가로 "절감/미절감"을 단독 판정하지 않는다.
3. **트래픽 요일 변동**: 10-17(토) 2,107,481 → 10-18(일, 부분 적용) 1,917,929. 일 총량만으로는 절감을 확정할 수 없다.
4. **배포 직후 캐시 콜드**: 첫 조회가 전부 D1 로 내려가 일시적으로 총량이 늘 수 있다.
5. **가드 공백 경로**: Worker SSR(`env.DB`)·`wrangler d1 execute`·빌드 프리렌더는 `cfnew.check_quota` 를 타지 않는다 — 이 경로가 만든 읽기는 가드가 보지 못한다(별도 승인 필요).
