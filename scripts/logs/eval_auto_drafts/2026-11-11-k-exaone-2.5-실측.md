TITLE: k-exaone-2.5 실측 — 7/12, 한 문항에 최대 285초

OpenCode에 등록된 LG AI Research의 **K-EXAONE 2.5**(한국어 특화 모델)입니다. 12문항으로 직접 돌려본 결과 **7/12**를 맞혔습니다. 결론부터 말하면 **보조 용도로만 권합니다**.

답변은 한국어로 자연스럽고, 12문항 모두 응답이 돌아왔습니다. 문제는 **속도**입니다 — 문항당 중간값 44초, 최대 285초, 12문항 합계 17분입니다. 같은 모델을 짧은 시간 예산으로 먼저 돌렸을 때는 3문항이 응답 실패로 빠졌는데, 예산을 늘리자 그 문항들이 답을 냈습니다. 능력이 아니라 시간 문제였습니다.

## k-exaone-2.5가 뭔가

- **모델 ID** — `exaone/k-exaone-2.5` (API 모델명 `k-exaone_v2.5`)
- **호출 옵션** — `reasoning_effort: low`, `temperature: 0.7`
- **컨텍스트** — 524,288 토큰 (설정값) · 니들 프로브 실측 하한도 524,288
- **가격** — 입력·출력 0 — 무료 API 키로 접근
- **지원** — 도구 호출 · 추론 강도 변형(`#high`/`#max`) 선택

가중치 공개 여부·학습 데이터·파라미터 수는 이번에 확인하지 않았습니다. 제조사 공식 자료로 대조하지 않은 값은 쓰지 않았습니다.

> 스펙은 OpenCode 설정에 적힌 값입니다(2026-11-11). 제조사 공식 문서로 대조하지는 않았습니다.

## 5분 안에 써보기

터미널 두 줄이면 확인됩니다.

```bash
opencode models | grep k-exaone-2.5
```

## 어떤 작업에 강한가

- **긴 대화·긴 문서 기억** (맥락 유지 2/2) — 12,000자 문서 중간의 함수명을 정확히 되받았고, 앞선 대화의 요청 3가지도 빠짐없이 복원했습니다.
- **코드 수정·리팩터링** (코딩 실무 2/4) — 중복 함수를 묶는 리팩터링과 로그 파서 작성은 제출 코드를 실제로 실행해 통과했습니다.
- **장애 원인 서술** (에이전트 2/4) — 타임아웃 원인을 한 문장으로 정리하고 diff까지 냈습니다.


## 어디서 걸리는가

12문항 중 5문항은 점수를 받지 못했습니다.

- **Q1 · 지시 이행** — 형식 실패입니다. 마지막 줄에 `---끝---`를 그대로 쓰라는 조건을 `끝---`로 어겼고, 영문 식별자도 포함됐습니다.
- **Q3 · 코딩 실무** — 실제 실패입니다. 버그 원인 설명은 정확했지만 제출한 코드가 검증 단언에서 실패했습니다(AssertionError).
- **Q4 · 코딩 실무** — 지시 미이행입니다. pytest 테스트를 새로 작성하라는 요청에, 이미 있는 테스트 자산을 다시 돌리겠다며 새 파일을 만들지 않았습니다(222초 소요).
- **Q11 · 에이전트(계획·도구·복구·판단)** — 형식 실패입니다. 4단계 계획은 만들었지만 JSON 최상위를 배열이 아니라 객체로 감쌌습니다(285초 소요).
- **Q12 · 에이전트(계획·도구·복구·판단)** — 채점기 오탐입니다. 답변은 '지금 바로(메일·느린 쿼리) / 오늘은 미뤄도 됨(버튼)'으로 정확히 나눴는데, 근거 문장에 들어간 '나중에'라는 단어 때문에 채점기가 그룹을 뒤집었습니다.

무료 키라고 해서 호출 한도가 없는 것은 아닙니다. 이번에는 한도에 걸리지 않았고, 실질적인 제약은 **응답 시간**이었습니다 — 문항당 중간값 44초, 최대 285초, 12문항 합계 17분입니다.

## 마무리 — 이럴 때 쓴다 / 이럴 때 쓰지 않는다

**쓴다**

- 한국어 문서를 읽고 요약·정리할 때 (응답이 올 때까지 기다릴 수 있는 작업)

- 응답 시간이 중요한 대화형 작업 — 최대 285초까지 걸렸습니다
- 형식이 정확히 정해진 산출물(마지막 줄 고정 문자열, JSON 최상위 구조)
- 여러 문항을 연속으로 돌리는 자동 평가·배치 작업
