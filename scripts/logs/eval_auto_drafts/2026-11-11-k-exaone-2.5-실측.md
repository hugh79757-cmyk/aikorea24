TITLE: k-exaone-2.5 실측 — 5/12, 12문항에 23분, 한국어는 되지만 느립니다

OpenCode에 등록된 LG AI Research의 **K-EXAONE 2.5**(한국어 특화 모델)입니다. 12문항으로 직접 돌려본 결과 **5/12**를 맞혔습니다. 결론부터 말하면 **지금은 권하지 않습니다**.

답변 자체는 한국어로 자연스럽게 나옵니다. 문제는 **속도**입니다 — 12문항을 끝까지 돌리는 데 23분이 걸렸고, 그중 3문항은 60초를 넘겨 180초까지 기다렸다가 결국 답을 받지 못했습니다. 아래에 실제로 받은 답과 걸린 지점을 그대로 적었습니다.

## 어떤 작업에 강한가

- **한국어 지시 이해** (지시 이행 1/2) — 한국어로 조건을 주면 문장 자체는 자연스럽게 나옵니다. 다만 '마지막 줄에 정확히 이 문자열' 같은 형식 조건은 자주 어깁니다.
- **긴 문서에서 정보 찾기** (맥락 유지 1/2) — 12,000자 문서 중간의 함수명을 찾아냈습니다. 이름만 답하라는 조건에 부연을 붙여 감점된 것이지, 못 찾은 것은 아닙니다.
- **코드 실행 검증 통과** (코딩 실무 1/4) — 4문항 중 1문항은 제출 코드를 실제로 실행해 통과했습니다. 나머지는 시간 초과 2문항, 단언 실패 1문항입니다.


## 어디서 걸리는가

12문항 중 7문항은 점수를 받지 못했습니다 (그중 3문항은 응답 시간 초과).

- **Q1 · 지시 이행** — 형식 실패입니다. 마지막 줄에 `---끝---`를 그대로 쓰라는 조건을 따옴표로 감싸 어겼습니다(`'---끝---'`).
- **Q3 · 코딩 실무** — 실제 실패입니다. 버그 원인 설명은 정확했지만 제출한 코드가 검증 단언에서 실패했습니다(AssertionError).
- **Q4 · 코딩 실무** — 응답 시간 초과입니다(60초 → 180초 재시도 후에도 응답 없음). 능력 실패가 아니라 측정 실패입니다.
- **Q5 · 코딩 실무** — 응답 시간 초과입니다(60초 → 180초 재시도 후에도 응답 없음). 능력 실패가 아니라 측정 실패입니다.
- **Q7 · 맥락 유지** — 형식 실패입니다. 함수명은 맞혔지만 뒤에 부연 설명을 붙여 '정확히 그 이름'이라는 조건을 어겼습니다.
- **Q11 · 에이전트(계획·도구·복구·판단)** — 형식 실패입니다. 4단계 계획은 만들었지만 JSON 최상위를 배열이 아니라 객체로 감쌌고, 단계 수도 4개가 아니었습니다.
- **Q12 · 에이전트(계획·도구·복구·판단)** — 응답 시간 초과입니다(60초 → 180초 재시도 후에도 응답 없음). 능력 실패가 아니라 측정 실패입니다.

무료 키라고 해서 호출 한도가 없는 것은 아닙니다. 이번에는 한도에 걸리지 않았지만, 실질적인 제약은 **속도**였습니다 — 12문항에 23분, 그중 3문항은 180초를 넘겨 응답을 받지 못했습니다.

## 한도와 비용 확인하는 법

무료라고 적혀 있어도 한도가 붙습니다. 실제로 확인하는 순서는 이렇습니다.

1. 설정에서 이 모델의 가격이 0인지 확인합니다 — 무료 표시가 없으면 유료 경로입니다.
2. `opencode run -m exaone/k-exaone-2.5 "한 단어로 대답: PONG"`로 한 번 호출해 봅니다. 첫 호출이 1초 안에 오면 연결은 정상입니다.

## 마무리 — 이럴 때 쓴다 / 이럴 때 쓰지 않는다

**쓴다**

- 한국어 문서를 읽고 요약·정리할 때 (응답이 올 때까지 기다릴 수 있는 작업)
- 정답이 하나로 정해지지 않은 설명형 답변이 필요할 때

**쓰지 않는다**

- 응답 시간이 중요한 대화형 작업 — 문항에 따라 180초를 넘겼습니다
- 형식이 정확히 정해진 산출물(마지막 줄 고정 문자열, JSON 최상위 구조)
- 여러 문항을 연속으로 돌리는 자동 평가·배치 작업

같은 모델을 두 번 측정했을 때 점수가 7/12와 5/12로 갈렸습니다(두 실행 모두 3문항은 시간 초과). 이 글은 저장소 컨텍스트를 배제한 조건의 5/12를 기준으로 씁니다.
