**한 줄 요약:** big-pickle은 OpenCode Zen이 한시 무료로 제공하는 스텔스 모델입니다. 20만 토큰 컨텍스트와 도구 호출을 지원하고, 제작사는 공개되지 않았습니다. AIK24가 OpenCode CLI로 12문항을 실측한 결과는 **8/12**(미응답 1문항 제외 시 8/11)였습니다.

## 1. big-pickle이란 — 확인된 것과 확인되지 않은 것

스텔스 모델은 연구소가 정식 공개 전에 이름과 제작사를 숨기고 풀어 실제 사용 데이터를 모으는 방식입니다. big-pickle도 OpenCode Zen 공식 문서에 스텔스 모델로 표기돼 있습니다.

> Big Pickle is a stealth model that's free on OpenCode for a limited time. The team is using this time to collect feedback and improve the model.
> — [OpenCode Zen 공식 문서](https://opencode.ai/docs/zen/)

확인된 항목과 확인되지 않은 항목을 나누면 다음과 같습니다.

| 구분 | 내용 | 출처 |
| --- | --- | --- |
| 확인됨 | 한시 무료 — 종료 시점은 공개되지 않았습니다 | [Zen 문서](https://opencode.ai/docs/zen/) |
| 확인됨 | 가격 — 입력·출력·캐시 읽기 모두 Free | [Zen 문서](https://opencode.ai/docs/zen/) |
| 확인됨 | 컨텍스트 200,000 · 입력 160,000 · 출력 32,000 토큰 | [models.dev](https://models.dev/) |
| 확인됨 | 추론(reasoning) · 도구 호출 · 구조화 출력 지원 | [models.dev](https://models.dev/) |
| 확인됨 | 입력·출력 모두 텍스트 — 이미지 입력 없음 | [models.dev](https://models.dev/) |
| 확인됨 | 모델 ID `big-pickle`, CLI ID `opencode/big-pickle` | `opencode models` 실측 |
| 미공개 | 제공사 · 가중치 · 파라미터 수 · 학습 데이터 | — |

2026년 10월 20일 조회 기준입니다. 컨텍스트·가격 같은 수치는 시점에 따라 바뀌므로, 실제로 쓰기 전에 [Zen 문서](https://opencode.ai/docs/zen/)와 [models.dev](https://models.dev/)에서 다시 확인하시기 바랍니다.

데이터 정책은 Zen의 기본 정책과 다릅니다. Zen은 평소 제로-retention과 학습 미사용을 명시하지만, big-pickle은 예외 목록에 이름을 올렸습니다.

> Big Pickle: During its free period, collected data may be used to improve the model.
> — [Zen 문서](https://opencode.ai/docs/zen/)

보관 기간은 이 문장에 적혀 있지 않습니다. 무료 기간 동안 수집된 데이터가 모델 개선에 사용될 수 있다는 것만 확인됩니다. 사내 저장소의 키·토큰·고객 데이터가 들어간 파일을 넣을 모델은 아닙니다.

## 2. OpenCode에서 사용하는 방법

OpenCode 2.0.32에서 확인한 화면 경로입니다. 설정 파일을 손으로 고치지 않아도 됩니다.

1. OpenCode를 실행하고 `/models`를 입력합니다. 또는 `ctrl+x`를 누른 다음 `m`을 누릅니다.
2. Search 칸에 `Free`를 입력합니다. 무료 모델만 남습니다.
3. 오른쪽 열에 `Free`가 붙은 줄에서 `big-pickle`을 찾아 Enter를 누릅니다.
4. 자주 쓸 모델이면 `ctrl+f`로 즐겨찾기에 넣어 둡니다. 다음부터는 `f2`로 최근 모델과 즐겨찾기를 전환할 수 있습니다.

선택 창의 전체 단축키는 [OpenCode 모델 문서](https://opencode.ai/docs/models/)와 [키바인드 문서](https://opencode.ai/docs/keybinds/)에 정리돼 있습니다.

| 항목 | 값 |
| --- | --- |
| 선택 창 표시명 | Big Pickle |
| 모델 ID (TUI) | `big-pickle` |
| 모델 ID (CLI·에이전트) | `opencode/big-pickle` |
| 컨텍스트 | 200,000 토큰 |
| 최대 출력 | 32,000 토큰 |
| 입력 형식 | 텍스트 |

**`:free` 접미사가 없다는 점을 주의해야 합니다.** OpenCode Zen의 무료 모델 상당수는 `mimo-v2.6-flash-free`, `space-bunny-free`처럼 이름에 `-free`가 붙습니다. big-pickle은 이름에 무료 표시가 없지만 Zen 문서의 무료 목록과 가격표에 `Free`로 올라 있습니다. 접미사만으로 무료 모델을 고르는 자동화를 만든다면 big-pickle을 놓치게 됩니다. 반대로 다른 모델에서 `:free`를 떼면 유료 항목으로 연결될 수 있으니, 무료 여부는 이름이 아니라 목록의 Free 표시와 가격표를 함께 확인하시기 바랍니다.

## 3. 12문항 실측 — 축별 결과

OpenCode CLI에서 4개 축 12문항을 실행했습니다. 채점은 사람이나 다른 모델이 아니라 문항별 결정적 채점 함수와 샌드박스 실행이 합니다. 같은 답에는 같은 점수가 붙습니다.

| 축 | 문항 수 | 결과 | 한 줄 판단 |
| --- | --- | --- | --- |
| 지시이행 | 2 | 1/2 | JSON만 출력은 통과. 1번은 채점기 오탐으로 0점(아래 설명). |
| 코딩실무 | 4 | 3/4 | 코드 수정·리팩터링·검증 함수 3문항 통과. pytest 작성은 180초 타임아웃. |
| 맥락유지 | 2 | 2/2 | 긴 문서의 함수명과 이전 대화 3가지를 모두 기억. |
| 에이전트 | 4 | 2/4 | 원인+diff, 즉시/미룸 분리는 통과. JSON 스키마 2문항은 형식 미달. |
| **합계** | **12** | **8/12** | 코딩 실무는 가능, 엄격한 형식 출력은 약함. |

**지시이행 1/2 — 1번 문항의 0점은 모델 실패가 아니라 채점기 오탐입니다.** 답안은 "한국어로 설명하고 마지막 줄에 `---끝---`를 출력하라"는 지시를 그대로 지켰습니다. 마지막 줄은 `---끝---`였고, 코드펜스 밖의 영어 토큰은 인라인 코드로 쓴 함수 이름 `add` 하나뿐이었습니다. 채점기는 코드펜스만 제거하고 인라인 코드는 남겨 두기 때문에 이 `add`를 영어 어휘로 셌습니다. 2번 문항(설명 없이 순수 JSON만 출력)은 정확히 통과했습니다.

**코딩실무 3/4 — 4번 문항은 응답 시간 문제입니다.** 코드 수정, 중복 제거 리팩터링, 입력 검증 함수 작성 3문항은 샌드박스에서 실제로 실행해 통과했습니다. pytest 테스트 작성 문항은 60초 안에 응답이 없어 180초로 재시도했지만 180초 안에도 응답하지 않았습니다. 모델이 틀린 답을 낸 것이 아니라 측정 시간 안에 답이 오지 않은 경우입니다.

**맥락유지 2/2 — 가장 안정적이었습니다.** 1,200자 문서의 특정 지점에 있는 함수 이름을 정확히 집어냈고, 이전 대화에서 요청한 작업 3가지를 모두 기억했습니다.

**에이전트 2/4 — 내용은 맞지만 형식이 어긋났습니다.** 장애 원인 설명과 unified diff, 긴급/지연 작업 분리는 통과했습니다. 반면 PR 리뷰 5개를 "문자열 배열"로 내라는 문항에는 `priority`·`item` 객체 배열을 냈고, 4단계 계획 문항에는 요구된 `screen`·`state_model`·`verify` 키 대신 다른 구조를 썼습니다. 계획의 내용 자체는 구체적이었지만 스키마가 달라 0점 처리됐습니다.

## 4. 이런 분께 추천합니다

- **코드를 고치고 검증하는 작업** — 수정·리팩터링·검증 함수 3문항이 샌드박스 실행을 통과했습니다. 결과를 사람이 검토할 수 있는 코드 작업에 맞습니다.
- **긴 문서에서 정보 찾기** — 20만 토큰 스펙과 별개로, 니들 테스트에서 256K 단계까지 통과했습니다. 문서 요약·근거 찾기에 쓸 수 있습니다.
- **한국어 설명과 요약** — 1번·8번 답안 모두 자연스러운 한국어였습니다. 영어 설명이 섞이지 않았습니다.
- **장애 원인 분석과 우선순위 분리** — 원인+diff 문항과 긴급/지연 분리 문항은 통과했습니다.

## 5. 솔직한 한계

- **제작사가 공개되지 않았습니다.** 문제가 생겨도 책임 소재를 확인할 수 없고, 가중치와 학습 데이터도 검증할 수 없습니다.
- **무료 기간의 데이터가 모델 개선에 사용될 수 있습니다.** 보관 기간은 공개되지 않았습니다. 민감한 코드와 개인정보를 넣지 마시기 바랍니다.
- **무료 기간이 언제 끝날지 예고가 없습니다.** Zen 문서는 한시 무료라고만 적습니다. 유료로 전환되거나 목록에서 사라질 수 있습니다.
- **텍스트 전용입니다.** 이미지·PDF를 직접 넣는 작업에는 쓸 수 없습니다.
- **엄격한 JSON 스키마 출력은 약합니다.** 문자열 배열, 정해진 키 이름, 4단계 계획처럼 형식을 고정한 자동화에는 그대로 쓰기 어렵습니다. 스키마 검증과 재시도를 붙여야 합니다.
- **긴 코드 생성은 시간이 걸릴 수 있습니다.** pytest 작성 문항은 180초 안에 응답이 오지 않았습니다. 대화형 즉답보다 결과를 기다리는 작업에 맞습니다.
- **`:free` 접미사가 없습니다.** 이름만 보고 무료 모델을 고르는 습관은 이 모델에서 통하지 않습니다.
- 모델에게 제작사를 물어도 그 답은 근거가 되지 않습니다. 스텔스 모델은 즉석에서 자기소개를 만들 수 있습니다.

## AIK24 실측 결과 (2026-10-20)

OpenCode CLI v2.0.32에서 `opencode run -m opencode/big-pickle --format json`으로 12문항을 실행했습니다. 채점은 문항별 결정적 채점 함수와 샌드박스 실행으로 했습니다.

| 항목 | 결과 |
| --- | --- |
| 종합 점수 | 8/12 (미응답 1문항 제외 시 8/11) |
| 지시이행 | 1/2 |
| 코딩실무 | 3/4 |
| 맥락유지 | 2/2 |
| 에이전트 | 2/4 |
| 실측 컨텍스트 | 262,144 (프로브 문서 기준 하한) |
| 토큰 사용량 | CLI 경유로 측정되지 않음 |

니들 컨텍스트 테스트는 8,192부터 두 배씩 올렸습니다. 8,192·16,384·32,768·65,536·131,072·262,144까지 6단계를 통과했고, 524,288 단계에서 실패했습니다. 표의 262,144는 통과한 마지막 단계입니다. 이 프로브는 문서 길이를 단위로 올리므로 토큰 수와 1:1로 같지 않습니다. "20만 토큰을 정확히 검증했다"는 뜻이 아니라, 그 이하에서 앞부분의 정보를 계속 기억했다는 뜻으로 읽어야 합니다.

1번 문항 0점은 위에서 설명한 채점기 오탐입니다. 답안은 한국어 설명과 마지막 줄 `---끝---`를 모두 지켰고, 코드펜스 밖 영어 토큰은 인라인 코드 `add` 하나뿐이었습니다. 이 0점을 빼면 9/12입니다. 다만 자동 채점 기록은 8/12이므로, 표에는 기록값을 그대로 적었습니다.

## 마무리 — 어디에 쓰면 좋은지

- **쓰기 좋은 자리:** 코드 수정·리팩터링, 긴 문서에서 근거 찾기, 한국어 요약, 장애 원인 분석과 diff 작성. 결과를 사람이 검토하는 작업에 맞습니다.
- **피해야 할 자리:** 정해진 JSON 스키마를 그대로 받아야 하는 자동화, 3분 이상 걸리는 대량 코드 생성, 민감한 코드·개인정보를 넣는 작업.
- **확인하지 않은 것:** 제공사, 가중치, 학습 데이터, 데이터 보관 기간. 이 항목은 공개되면 다시 확인해야 합니다.

바로 써 보려면 세 단계면 됩니다. `/models`에서 `big-pickle`을 고르고, 결과를 검토할 수 있는 코드 작업에 먼저 붙이고, 민감한 정보는 넣지 마십시오.
