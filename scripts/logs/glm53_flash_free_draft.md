OpenCode Zen에 GLM-5.3-Flash Free가 새로 올라왔습니다. 모델 ID는 `glm-5.3-flash-free`이고, 요금표상 입력·출력·캐시 읽기 전부 Free입니다. 다만 OpenCode 안에서 고르는 무료 항목은 벤더 스펙과 상한이 다릅니다 — 벤더 문서의 컨텍스트 1M·최대 출력 128K가 무료 항목에서는 200K·32K로 잘려 있습니다. 왜 잘려 있는지, 어디서 고르면 되는지, 실제로 어느 정도 성능인지를 12문항 실측으로 확인했습니다.

한시적 무료라는 점이 중요합니다. 종료 시점은 공개되지 않았습니다. 같은 이유로 이 모델을 사내 코드에 쓰기 전에 데이터 정책을 한 번 확인하시는 편이 좋습니다 — 무료 경로는 제로 리텐션이지만, 아래에 정리한 다른 무료 경로의 정책은 별개입니다.

## 2. 등록된 무료 경로와 상한

모델 ID에 `-free`가 붙은 항목이 무료입니다. 등록 정보 기준으로 무료 경로가 세 곳 있고 상한이 서로 다릅니다.

| 경로 | 모델 ID | 컨텍스트 | 최대 출력 | 비고 |
| --- | --- | --- | --- | --- |
| OpenCode Zen | `opencode/glm-5.3-flash-free` | 200,000 | 32,000 | 한시적 무료 · 제로 리텐션 |
| OrcaRouter | `orcarouter/z-ai/glm-5.3-flash-free` | 1,000,000 | 128,000 | 무료 표기. 제 환경에서는 호출 실패(4절) |
| TokenRouter | `tokenrouter/z-ai/glm-5.3-free` | 1,000,000 | 131,072 | `Flash`가 아닌 GLM-5.3 본체. 제 환경에서는 호출 실패(4절) |
| Zen 유료 | `opencode/glm-5.3-flash` | 1,000,000 | 131,072 | 입력 $0.15 · 출력 $0.50 (100만 토큰당) |

등록돼 있다고 해서 바로 쓸 수 있는 것은 아닙니다. 상한이 큰 경로일수록 별도 키나 자체 무료 한도를 요구하는 경우가 많아, 실제 호출 결과는 4절에 정리했습니다.

접미사를 떼면 유료 항목으로 연결됩니다. `glm-5.3-flash-free`를 `glm-5.3-flash`로 줄여 쓰면 유료 과금 대상이 됩니다. 목록에서 고를 때도 ID 마지막 글자까지 확인하시는 편이 안전합니다.

## 3. 화면에서 고르는 법

OpenCode를 실행한 상태에서 `/models`를 입력하거나, `ctrl+x`를 누른 뒤 `m`을 누릅니다. 모델 목록 창이 열리면 검색창에 `glm`을 입력해 후보를 좁힙니다. 무료 항목은 오른쪽 열에 `Free` 라벨이 붙습니다.

```text
/models          모델 목록 열기 (키바인드 model_list = <leader>m, leader 기본값 ctrl+x)
ctrl+f           보고 있는 모델을 즐겨찾기에 넣기
f2 / shift+f2    최근에 쓴 모델로 앞뒤 전환
ctrl+t           추론 강도 변형 순환 (low · high · max)
ctrl+a           제공자 목록
esc              창 닫기
```

`ctrl+t`는 사고 강도를 바꾸는 키입니다. GLM-5.3-Flash Free는 low·high·max 세 단계를 제공하므로, 이 키를 누를 때마다 단계가 바뀝니다. 문서에도 `ctrl+t`로 모델 변형을 순환한다고 적혀 있습니다 — `/thinking`은 사고 과정을 화면에 보여줄지만 결정하고, 실제 사고 강도를 바꾸지는 않습니다.

같은 선택을 명령줄에서 재현하려면 모델 ID 뒤에 `#`과 변형 이름을 붙입니다.

```bash
opencode run -m opencode/glm-5.3-flash-free "이 함수의 버그를 찾아줘"
opencode run -m opencode/glm-5.3-flash-free#low "이 함수의 버그를 찾아줘"
opencode run -m opencode/glm-5.3-flash-free#max "이 함수의 버그를 찾아줘"
```

한 번 고른 모델은 OpenCode가 기억합니다. 다음 실행에서 `-m`을 주지 않으면 마지막에 쓴 모델로 열립니다. 그래서 무료 모델을 골라 두고 쓰다가, 작업이 무거워질 때만 유료 항목으로 바꾸는 식으로 운용할 수 있습니다. 설정 파일에 고정하려면 `opencode.json`의 `model` 항목에 적습니다.

### 응답 시간과 60초 벽

12문항 전체는 약 8분이 걸렸습니다(문항당 평균 약 41초). 그중 2문항은 60초 안에 끝나지 않아 180초로 늘려 재시도했고, 재시도에서는 두 문항 모두 완료됐습니다. 실패가 아니라 지연입니다.

동일한 프롬프트로 변형별 3회씩 반복해 시간을 쟀습니다. 12회 모두 응답했고, 같은 조건에서 2.8초에서 75.8초까지 벌어졌습니다.

자동화에 넣을 때 걸리는 지점이 여기입니다. 타임아웃을 60초로 잡으면 같은 문항이 어떤 회차에는 통과하고 어떤 회차에는 걸립니다. 위의 '60초 벽'이 그 예이고, 12문항 중 2문항이 여기에 걸렸습니다.

### 파일 수정까지 되는지 (도구 사용)

버그가 있는 파이썬 파일 하나를 임시 디렉터리에 두고 "직접 수정해 달라"고 시켰습니다. 20.6초에 끝났고, 모델은 파일을 읽어 원인을 짚은 뒤 파일을 실제로 고쳤습니다.

- 수정 전: `return subtotal * tax_rate` (세금액만 반환)
- 수정 후: `return subtotal + subtotal * tax_rate` (합계에 세금 가산)

고친 뒤에는 `python3`로 직접 실행해 결과를 확인하고 근거와 함께 보고했습니다. 무료 항목이라도 파일 읽기·수정·실행까지 도구를 쓰는 작업은 됩니다.

여기서 걸린 지점이 하나 있습니다. 이 환경에서 `opencode run`은 실행 중인 서비스의 워크스페이스에 붙습니다. 그래서 임시 디렉터리에서 옵션 없이 돌린 첫 시도에서는 모델이 이 저장소를 워크스페이스로 보고 다른 디렉터리의 파일을 찾지 못했습니다. `--standalone`(전용 서버)과 `--auto`(권한 자동 승인)를 켜고 작업 디렉터리와 `PWD`를 그 디렉터리로 맞추자 파일을 찾아 고쳤습니다.

같은 이유로 응답 시간을 재던 호출 하나에서는 모델이 저장소의 기록 파일에 답변 요약을 남기는 부수 작업까지 했습니다(그 파일에는 제 프롬프트가 '사용자 질문'으로 기록됐습니다). 무료 모델을 스크립트로 돌릴 때는 작업 디렉터리를 분리하고 도구 권한을 확인하시는 편이 안전합니다.

### 무료 티어는 OpenCode 안에서만 열립니다

환경변수에서 키와 토큰 항목을 모두 제거하고 저장된 자격증명 파일도 없는 상태에서 CLI로 무료 경로를 호출했더니 9.1초에 `4`가 돌아왔습니다. 키가 없어도 OpenCode 안에서는 동작합니다.

반대로 같은 엔드포인트를 밖에서 두드려 봤습니다.

```bash
curl -s https://opencode.ai/inference/openai/v1/chat/completions \
  -H 'Content-Type: application/json' \
  -d '{"model":"glm-5.3-flash-free","messages":[{"role":"user","content":"2+2는? 숫자만 답하세요."}]}'
```

이 호출은 403으로 막혔습니다. 제 환경에 있던 Zen 토큰을 인증 헤더로 붙인 경우에도 같은 403이었습니다. 응답 본문은 이랬습니다.

> {"type":"error","error":{"type":"FreeTierError","message":"OpenCode's free tier can only be used from within OpenCode. Download it at https://opencode.ai and keep building."}}

무료 티어는 자격증명이 아니라 호출 주체를 보고 막습니다. 그래서 키가 없어도 OpenCode 안에서는 돌고, 밖에서는 키를 붙여도 막힙니다(Console에서 새로 발급한 API 키라면 결과가 다를 수 있습니다). 자체 스크립트에 OpenAI 호환 클라이언트로 붙여 쓰려던 계획이 있었다면 이 지점에서 막히므로, 그런 용도에는 유료 항목(`glm-5.3-flash`)을 써야 합니다.

### 이 실측의 조건

- 문항 실행은 이 저장소 디렉터리에서 이뤄졌습니다. 그래서 모델이 저장소 파일과 세션 기록을 문맥으로 함께 봤고, 실제로 코딩 실무 ②·에이전트 ① 답변에 저장소 경로와 '이전 세션' 언급이 들어갔습니다. 모델 능력만 분리한 측정이 아닙니다.
- 채점에 쓰인 답변은 문항당 1,000자까지 보관됩니다. 코딩 실무 ②·에이전트 ③·④는 그 상한에 닿아 앞부분만 확인했습니다.
- 이 환경에는 전역 지침 파일이 있고 OpenCode가 세션마다 이를 자동으로 넣습니다. 실제로 도구 사용 스모크 테스트의 답변이 그 지침의 보고 형식(`[검증됨]`·근거 표기)을 그대로 따랐습니다. 형식 관련 문항 점수에 이 지침이 영향을 줬을 수 있습니다.
- 도구 사용 스모크 테스트와 무키 호출은 위에 적은 옵션 조건(`--standalone`·`--auto`, `PWD` 교정, 키·토큰 변수 74개 제거)에서 측정했습니다. 옵션 없이 같은 작업을 시키면 결과가 달라질 수 있습니다.
- 응답 시간 측정은 도구 사용이 가능한 조건(저장소 워크스페이스)에서 이뤄졌습니다. 순수 추론 시간만 분리한 값이 아닙니다.
- 무료 경로 호출 실패 3건은 제 환경의 자격증명·무료 한도 상태에서 나온 결과입니다. 다른 계정에서는 다를 수 있습니다.

## 5. 한계

- 한시적 무료입니다. 종료 시점이 공개되지 않았으므로, 이 모델에 의존하는 자동화를 걸어 두었다면 목록에서 사라졌을 때를 대비해야 합니다.
- 무료 경로의 최대 출력은 32,000 토큰입니다. 벤더 스펙 128K의 4분의 1이므로, 파일 하나를 통째로 다시 쓰게 하는 작업에서는 출력이 잘릴 수 있습니다.
- 무료 경로 컨텍스트는 200,000 토큰입니다. 저장소 전체를 넣는 작업은 상한에 먼저 걸립니다.
- 사고 모드를 끌 수 없습니다. 짧은 질문에도 사고 토큰이 붙으므로 지연이 늘어납니다.
- 무료 경로의 데이터 정책은 제로 리텐션으로 확인되지만, 같은 모델의 다른 무료 경로 정책은 각 제공자 문서를 따로 확인해야 합니다.

## 마무리 — GLM-5.3-Flash Free를 어디에 쓰면 좋은가

- 코드 읽기와 요약: 컨텍스트 200K 안에 들어가는 파일 몇 개를 통째로 넣고 구조를 설명하게 하는 작업에 맞습니다.
- 짧은 함수 단위 수정: 출력 32K 안에서 끝나는 함수 단위 수정은 무리 없이 처리합니다.
- 이미지·영상이 섞인 입력: 입력 모달리티에 영상·이미지·파일이 포함된 모델이므로, 스크린샷을 넣고 화면을 읽히는 작업에 쓸 수 있습니다.
- 저장소 전체 리팩터링이나 대형 파일 재생성은 유료 항목(`glm-5.3-flash`)이나 다른 모델로 넘기는 편이 낫습니다. 무료 경로의 출력 상한 32K에 먼저 걸립니다.
- 토큰 비용이 0이라 하더라도 사고 모드를 끌 수 없어 응답 시간이 길어집니다. 지연에 민감한 자동화에 그대로 넣기 전에 실측이 필요합니다.
- 아직 확인하지 않은 것: 이미지·영상 입력의 실제 인식 품질, 도구 호출 정확도, 32K 출력 상한에 걸리는 정확한 지점은 이번 실측 범위가 아닙니다.
